# 비교 분석 보고서: Make vs Zapier

> ⚠️ **Zapier 는 아직 직접 사용하지 못해 비교 불가.** 아래 표의 Zapier 칸은 구현 후 채울 것. Make 칸의 "직접 확인"은 실제 사용 경험.

## 1. 사용한 도구

| 도구 | 플랜 | 사용 기간/일자 |
|---|---|---|
| Make | Free | 2026-11-18 (실사용) |
| Zapier | Free | ⏳ 미사용 |

## 2. 구현 과정 요약

- 구현 대상: 폼 제출(Webhook) → 점수 분기(≥80 pass / <80 fail) → 기록 + 결과 변수 ([상세](README.md))
- Make: Webhook→Router→Data store→Set variable 구성. Google 연동 없이 가능했고 pass/fail 두 경로 모두 실행 확인. 막힌 점: 무료 Data store 용량(1MB)이 첫 저장소로 소진되어 두 번째 프로젝트에서 저장소를 만들 수 없었음. 캔버스 편집은 AI 어시스턴트(Maia)로 상당 부분 단축.
- Zapier: _(한두 문단: 막힌 점, 걸린 시간)_

## 3. 비교표

> `직접 확인` 칸은 **본인이 사용하며 느낀 점**으로 채웁니다. 무료 플랜 수치는 작성 시점의 공식 요금제 페이지로 확인해 기입하세요(수시로 바뀜).

| # | 항목 | Make | Zapier | 직접 확인 |
|---|---|---|---|---|
| 1 | UI/UX | 캔버스에 노드를 연결하는 시각적 방식 | 위에서 아래로 쌓는 리스트(스텝) 방식 | Make: 분기가 한눈에 보임. 단 줌/좌표 조작이 까다로움 |
| 2 | 설정 난이도 | 초기 학습 곡선 있음, 데이터 매핑 자유도 높음 | 직관적, 입문 쉬움 | |
| 3 | 조건 분기 | Router로 다중 경로를 한 화면에서 표현 | Filter(중단) / Paths(분기), 플랜별 제약 가능 | |
| 4 | 연동 서비스 범위 | 다수 앱 지원 | 매우 많은 앱 지원(커넥터 수 최다급) | |
| 5 | 무료 플랜 범위 | Operations 기준 월 한도 | Tasks 기준 월 한도, 스텝·기능 제한 | Make: Data store 총 1MB 제한을 실제로 겪음 |
| 6 | 실행 로그 확인 | Execution History에서 모듈별 입출력 데이터 확인 | Zap/Task History에서 단계별 결과 확인 | Make: 실행별 Operations 수로 필터 통과/차단 구분 가능 |
| 7 | 에러 처리 | Error handler 라우트 설정 가능 | 자동 재시도·알림 설정 | |
