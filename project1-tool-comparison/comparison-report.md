# 비교 분석 보고서: Make vs Zapier

> 두 도구 모두 직접 구현·실행함. "직접 확인" 칸은 실제 사용 경험.

## 1. 사용한 도구

| 도구 | 플랜 | 사용 기간/일자 |
|---|---|---|
| Make | Free | 2026-11-18 (실사용) |
| Zapier | Professional 14일 체험(Webhooks·Paths 사용 위해) | 2026-11-18 (실사용) |

## 2. 구현 과정 요약

- 구현 대상: 폼 제출(Webhook) → 점수 분기(≥80 pass / <80 fail) → 기록 + 결과 변수 ([상세](README.md))
- Make: Webhook→Router→Data store→Set variable 구성. Google 연동 없이 가능했고 pass/fail 두 경로 모두 실행 확인. 막힌 점: 무료 Data store 용량(1MB)이 첫 저장소로 소진되어 두 번째 프로젝트에서 저장소를 만들 수 없었음. 캔버스 편집은 AI 어시스턴트(Maia)로 상당 부분 단축.
- Zapier: Catch Hook → Paths(A/B) → Email by Zapier 구성. 트리거/액션 추가가 단계 목록 형태라 직관적이었으나, 분기용 Paths 와 Webhook 트리거가 유료(체험판) 기능이었음. 필드 매핑 피커(Insert data)는 작은 팝업이라 다루기 까다로워 이메일 본문은 고정 문구로 설정.

## 3. 비교표

> `직접 확인` 칸은 **본인이 사용하며 느낀 점**으로 채웁니다. 무료 플랜 수치는 작성 시점의 공식 요금제 페이지로 확인해 기입하세요(수시로 바뀜).

| # | 항목 | Make | Zapier | 직접 확인 |
|---|---|---|---|---|
| 1 | UI/UX | 캔버스에 노드를 연결하는 시각적 방식 | 위에서 아래로 쌓는 리스트(스텝) 방식 | Make: 분기가 한눈에 보임. 단 줌/좌표 조작이 까다로움 |
| 2 | 설정 난이도 | 초기 학습 곡선 있음, 데이터 매핑 자유도 높음 | 직관적, 입문 쉬움 | 둘 다 가능. Zapier 는 순서대로 설정, Make 는 모듈 연결 후 매핑 |
| 3 | 조건 분기 | Router로 다중 경로를 한 화면에서 표현 | Filter(중단) / Paths(분기), 플랜별 제약 가능 | Make: Router+Filter 무료로 사용. Zapier: Paths 는 체험판 기능 |
| 4 | 연동 서비스 범위 | 다수 앱 지원 | 매우 많은 앱 지원(커넥터 수 최다급) | 이번에는 외부 앱 연동 없이 내장 기능만 사용해 차이는 확인하지 못함 |
| 5 | 무료 플랜 범위 | Operations 기준 월 한도 | Tasks 기준 월 한도, 스텝·기능 제한 | Make: Data store 총 1MB 제한을 겪음. Zapier: Webhooks(Premium)·Paths 가 무료 범위 밖 |
| 6 | 실행 로그 확인 | Execution History에서 모듈별 입출력 데이터 확인 | Zap/Task History에서 단계별 결과 확인 | Make: 실행별 Operations 수로 통과/차단 구분. Zapier: 실행 상세에서 Path 가 활성/회색으로 시각 표시 |
| 7 | 에러 처리 | Error handler 라우트 설정 가능 | 자동 재시도·알림 설정 | 이번 과제에서는 에러 처리 미구현 |

## 4. 도구별 장단점

### Make
- 장점: 분기(Router)를 한 캔버스에서 보여주고 무료로 사용 가능. 내장 AI(Maia)로 구성 속도를 높일 수 있음. 실행 로그에 모듈별 데이터가 남음.
- 단점: 캔버스 줌/조작이 어렵고 초기 학습이 필요. 무료 Data store 용량이 작음.

### Zapier
- 장점: 단계가 위에서 아래로 정리되어 처음 써도 구조 파악이 쉬움. 실행 기록에서 Path 활성/차단이 한눈에 보임.
- 단점: 이번 구성에 쓴 Webhook 트리거(Premium)와 Paths 가 무료 범위 밖. 체험 종료 후 유지하려면 유료 업그레이드 필요.

## 5. 어떤 상황에 적합한가

- Make가 적합: 분기가 있고 데이터를 가공하는 워크플로우를 무료/저비용으로 만들고 싶을 때.
- Zapier가 적합: 연동 앱이 많고 빠르게 단순 흐름을 만들고 싶을 때, 유료 플랜 예산이 있을 때.

## 6. 유료 기능 사용 여부

- [ ] 없음 (무료 플랜만 사용)
- [x] 있음 (Zapier)
  - 사용 기능: Webhooks by Zapier(Catch Hook, Premium 앱), Paths — 14일 Professional 체험판으로 사용.
  - 불가피했던 이유: 과제 샘플 구조(폼 제출 → 점수 분기)를 외부 계정 연동 없이 동일하게 재현하려고 Webhook 트리거와 분기가 필요했음.
  - 무료 대안: 트리거를 Google Forms / Google Sheets(무료 앱)로 바꾸고, 분기는 Filter 2개 Zap 으로 분리. (구글 계정 연동 필요)
  - 비용: 결제하지 않음. 체험 종료 후에는 Zap 이 중단됨.

## 7. 결론

이 워크플로우(분기 + 기록)는 **Make** 를 선택. 같은 구조를 무료 범위에서 완성할 수 있었고 분기가 한 화면에 보이기 때문. 다만 Zapier 가 처음 접하는 사람에게는 설정 흐름이 더 직관적이었음.
